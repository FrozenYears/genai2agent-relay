# Action 封套与纯思考回复小修记录

## 范围

这些修改均位于独立的 `genai2agent-relay` 仓库，不改变客户端协议或工具执行端。保留严格 JSON、工具白名单、参数 Schema 校验及现有重试次数；不自动补括号，不新增日志功能、配置项或依赖。

## 第一次：说明文字被误判为工具调用

原因：正文用反引号展示 `@@ACTION@@{...}@@END_ACTION@@` 时，旧解析器仍将标记当成真实调用，随后因封套不在结尾而拒绝整段回复。

修改：跳过已闭合的单行反引号引用及配对的反引号/波浪线代码围栏（围栏长度一致）。找到引用外的真实调用起点后，不扫描参数中的 Markdown，避免误伤合法参数。

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| 正文引用 action 示例 | 可能返回 502 | 返回正文，不执行工具 |
| 引用后跟合法真实调用 | 需要兼容 | 仍识别真实调用 |
| 参数含反引号或 action 标记 | 应保留参数 | 保持参数不变 |
| 真实调用未闭合或 JSON 非法 | 拒绝 | 仍拒绝 |

边界：这不是完整 Markdown 解析器；未闭合或不支持的引用仍按严格规则处理。实际调用不得包进 Markdown；自动工具选择模式下，引用内调用作为文本返回，不能执行。

## 第二次：JSON 重试缺少具体纠错信息

原因：一个双调用封套在第一个 `parameters` 后少了关闭调用对象的 `}`。旧代码已有一次自动重试，但丢弃 JSON 解析原因，只笼统要求重新序列化。

修改：保留 `JSONDecodeError` 异常原因，仅在 JSON 语法错误时将原因、封套内 JSON 的行列号加入已有重试提示，要求完整重发而不是补丁。失败回复原本就在重试历史中，无需再次复制参数。回溯封套起点时更新诊断，避免选中参数内嵌标记对应的错误位置。

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| JSON 语法错误后的重试 | 泛化提示 | 提示具体原因及行列号 |
| 重试修正成功 | 交付工具调用 | 不变 |
| 重试仍失败 | 502 / api_error | 不变，客户端错误文本不变 |
| 非 JSON 语法错误 | 原有重试提示 | 不变 |
| 日志、次数、超时、配置 | 原有行为 | 不变 |

该改动提高纠错信息质量，不保证模型第二次一定修正，也不解决平台网页未显示回复的原因。未新增逐次诊断日志。

## 第三次：只有深度思考时请求继续

样例：上游的深度思考块仅返回 `Let me run a few checks.`，正文为空，没有实际 action。旧逻辑只要 thinking 非空，就会返回成功及 `end_turn`，导致客户端没有可执行的调用。

现在正文为空或仅有空白时，使用已有重试机会发送：

> 上一次没有返回正文或实际工具调用，未执行任何操作。请继续。如果需要操作，请输出完整合法的 @@ACTION@@ JSON 封套，并以 @@END_ACTION@@ 结束；不要只输出思考或行动计划。

不将思考转为正文，不把空 assistant 消息追加到历史。重试返回正常正文或合法调用即可继续；仍无正文则返回 `First-hop model returned no answer or action`，Messages 接口为 HTTP 502。完全空回复也使用这条提示，不再错误地归为序列化问题。

与 JSON 错误共用原有重试预算，不额外增加一次；重试配置为 0 时直接拒绝。正常正文无需工具也能成功返回；正文中仅有行动计划仍属于正文，不做语义猜测。该防护不能保证上游会继续产出有效结果。
