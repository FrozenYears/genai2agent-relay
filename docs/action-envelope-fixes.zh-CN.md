# Action 封套与纯思考回复小修记录

## 范围

这些修改均位于独立的 `genai2agent-relay` 仓库，不改变客户端协议或工具执行端。保留严格 JSON、工具白名单、参数 Schema 校验及现有重试次数；不自动补括号，不新增日志功能、配置项或依赖。

## 第一次：说明文字被误判为工具调用

原因：正文用反引号展示 `@@ACTION@@{...}@@END_ACTION@@` 时，旧解析器仍将标记当成真实调用，随后因封套不在结尾而拒绝整段回复。

修改：跳过已闭合的单行反引号引用及配对的反引号/波浪线代码围栏（围栏长度一致）。找到引用外的真实调用起点后，不扫描参数中的 Markdown，避免误伤合法参数。

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| 正文引用 action 示例 | 可能返回 502 | 返回正文，不执行工具 |
| 引用后跟合法真实调用 | 需要兼容 | 仍识别真实调用 |
| 参数含反引号或 action 标记 | 应保留参数 | 保持参数不变 |
| 真实调用未闭合或 JSON 非法 | 拒绝 | 仍拒绝 |

边界：这不是完整 Markdown 解析器；未闭合或不支持的引用仍按严格规则处理。实际调用不得包进 Markdown；自动工具选择模式下，引用内调用作为文本返回，不能执行。

## 第二次：JSON 重试缺少具体纠错信息

原因：一个双调用封套在第一个 `parameters` 后少了关闭调用对象的 `}`。旧代码已有一次自动重试，但丢弃 JSON 解析原因，只笼统要求重新序列化。

修改：保留 `JSONDecodeError` 异常原因，仅在 JSON 语法错误时将原因、封套内 JSON 的行列号加入已有重试提示，要求完整重发而不是补丁。失败回复原本就在重试历史中，无需再次复制参数。回溯封套起点时更新诊断，避免选中参数内嵌标记对应的错误位置。

| 情况 | 修改前 | 修改后 |
| --- | --- | --- |
| JSON 语法错误后的重试 | 泛化提示 | 提示具体原因及行列号 |
| 重试修正成功 | 交付工具调用 | 不变 |
| 重试仍失败 | 502 / api_error | 不变，客户端错误文本不变 |
| 非 JSON 语法错误 | 原有重试提示 | 不变 |
| 日志、次数、超时、配置 | 原有行为 | 不变 |

该改动提高纠错信息质量，不保证模型第二次一定修正，也不解决平台网页未显示回复的原因。未新增逐次诊断日志。

## 第三次：只有深度思考时请求继续

样例：上游的深度思考块仅返回 `Let me run a few checks.`，正文为空，没有实际 action。旧逻辑只要 thinking 非空，就会返回成功及 `end_turn`，导致客户端没有可执行的调用。

现在正文为空或仅有空白时，使用已有重试机会发送：

> 上一次没有返回正文或实际工具调用，未执行任何操作。请继续。如果需要操作，请输出完整合法的 @@ACTION@@ JSON 封套，并以 @@END_ACTION@@ 结束；不要只输出思考或行动计划。

不将思考转为正文，不把空 assistant 消息追加到历史。重试返回正常正文或合法调用即可继续；仍无正文则返回 `First-hop model returned no answer or action`，Messages 接口为 HTTP 502。完全空回复也使用这条提示，不再错误地归为序列化问题。

与 JSON 错误共用原有重试预算，不额外增加一次；重试配置为 0 时直接拒绝。正常正文无需工具也能成功返回；正文中仅有行动计划仍属于正文，不做语义猜测。该防护不能保证上游会继续产出有效结果。

## 第四次：开始标记少字符导致调用原样返回

截图中的开头是 `@@ACTION@{`，正确形式是 `@@ACTION@@{`。旧逻辑找不到完整标记，就以普通正文返回并结束。命令还存在独立的 JSON 转义问题：`"command":"python -c "import json""` 应写成 `"command":"python -c \"import json\""`。

现在引用之外的 `@@ACTION@`，或在有效开始标记之前出现的 `@@END_ACTION@@`，会被视为损坏封套，使用已有重试提示指出正确标记并提醒字符串转义。不会自动补字符并执行。代码引用中的示例及合法调用参数里的这些字符串保持原处理；未覆盖的其他拼写错误不做宽泛猜测。

前后对比：此前 HTTP 200 原样返回损坏封套；现在重试修正后交付调用，仍损坏则 HTTP 502。仅修好标记但 JSON 仍非法，也继续拒绝。仍与其他错误共用原有重试预算。

验证：26 项中继测试通过。合成上游的 Messages 路由验证了完整修正后 HTTP 200 / tool_use、标记仍错 HTTP 502、只修标记而 JSON 仍错 HTTP 502，每组两次尝试，未执行命令。第四次提交标题为 `fix: reject malformed action opening delimiters`，可单独 revert；需要全部回滚时先撤销最新修改。

## 第五次：长上下文的协议遵循与截断区分

用户实测体感是长上下文更容易报错。本地代码原先把完整工具定义放在第一条 user 消息，只在最近一轮追加通用提醒；这不利于模型对照当前接口。改进依据该观察实施，尚未通过真实模型对照量化效果，不将其等同于已证实的“模型幻觉”。

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 完整工具 Schema | 历史开头 | 最近一条 user 消息尾部，替代通用提醒，不再在开头重复注入 |
| 用户规则、历史、附件 | 保留 | 继续保留，不自动摘要或删除 |
| 调用对象字段错误 | 泛化重试 | 指明 calls 索引及必须使用 operation/parameters 的结构 |
| 参数格式、Schema 错误 | 泛化重试 | 指明约束、缺失必填字段，并仅重发相关工具的当前定义 |
| finish_reason=length | 被丢弃，可能误报空回复或 JSON 错误 | 明确长度截断，立即失败，不以相同预算重复生成 |

当前定义优先于模型记忆中的同名工具接口。比如 edit 参数错误使用 old_string 而缺少 input 时，重试反馈缺失 input，并给出当前 edit Schema；不自动转换参数。未知工具只反馈允许的工具名，不猜测应映射到哪个工具。

截断返回 `First-hop output was truncated (finish_reason=length)` 开头的错误；即使正文看起来包含完整调用，也不交付，因为整个生成未完整结束。思考计入第一跳本地 max_tokens，relay 不自动加预算或关闭思考。正常结束但正文为空仍沿用“请继续”的现有重试。

验证：29 项中继测试通过，覆盖近期 Schema、历史与图片保留、字段纠错、参数纠错，以及第一跳 HTTP 返回 length 时不执行且不重试。Messages 路由验证参数修正后 HTTP 200、两次请求；长度截断 HTTP 502、一次请求。使用合成上游，未执行工具、未测真实长会话成功率。

本次提交标题为 `fix: improve current tool context and validation recovery`。保留原重试上限，不新增日志、配置或依赖，不新增临时文件。最新改动优先 revert，再撤销之前的修改。

## 第六次：代码块与 XML 调用返回前纠错

200k–500k 上下文中，模型出现了 JSON 代码块内直接输出调用数组，或使用 `<parameter name="calls">[...]</parameter>` 的情况。旧逻辑找不到标准 action 起点，就将其当正文返回 end_turn，客户端没有工具可执行而停止。

现在在没有标准 action 起点、准备返回普通文本之前检查这些包装。仅匹配非空调用数组（或包含 calls 的对象），调用具有当前允许的 operation 和对象参数；损坏 JSON 也可通过明确的首项 operation/parameters 前缀识别。支持 JSON/无语言代码围栏（反引号或波浪线，闭合或延伸至回复末尾）及完整 calls XML 标签。不泛化到任意 JSON/XML，不执行替代格式，不从 thinking 提取操作。

识别后使用既有重试预算，请模型继续并完整重发标准 action 封套；纠正并校验通过才交付客户端，仍然失败则返回明确错误，不将原始调用串作为成功正文返回。流式请求同样先验证、后交付。正常 action 参数内部的代码或 XML 不受影响。

按用户确认的取舍，符合上述调用结构的展示示例也会触发纠错；不再为这类示例保留放行例外。未匹配的其他格式不保证识别，已返回客户端的旧回复无法追溯处理。

验证：32 项中继测试通过。覆盖替代格式、普通数据、真实调用参数，以及流式返回前纠错成功/预算耗尽。Messages 合成上游烟雾验证：第二次标准调用返回 HTTP 200 / tool_use；持续 XML 调用两次后 HTTP 502。没有调用真实模型或执行工具，未生成临时文件。

本次提交标题 `fix: retry alternate tool syntax before text delivery`；与之前修改一样可独立 revert，不新增日志、依赖、配置或重试次数。
